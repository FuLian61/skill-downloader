# 热门技能定时同步

## 1. 实现范围

该功能不依赖网页表单。Java 17 的单线程 `ScheduledExecutorService` 调用 `SkillSyncService.runOnce(false)`，按平台拉榜单，再复用现有下载器下载每个技能的 ZIP。只保存文件，不安装、不执行技能内容。

默认两个平台**分别前 50**，一轮目标最多 100 个。平台接口不足 50、凭证无效、限流或个别下载失败时，记录实际结果，不用重复技能或其他榜单凑数。平台榜单各自定义热度，不能把两个榜单的排名直接比较。

## 2. IDEA 运行

1. 用 Maven 项目导入，Project SDK 使用 JDK 17 或以上。
2. 运行类选择 `dev.skills.SkillSyncMain`。
3. Working directory 设置为本项目目录 `skill-downloader`。
4. 首先填 Program arguments：`--sync-list`。这只保存榜单和报告，不下载 ZIP。
5. 配置所需环境变量后，用 `--sync-once` 做一轮下载；确认输出正常再用 `--schedule` 常驻运行。
6. IDEA 的 Stop 或终端 Ctrl+C 停止任务；关闭进程后不会继续调度。无参数运行 `SkillSyncMain` 等同于 `--schedule`，会立即下载。

原入口 `dev.skills.SkillDownloader` 也支持这三个参数；网页模式 `--serve` 不会隐式启动同步。需要两者时分别启动两个进程。

## 3. 命令行与配置

构建后，在项目目录执行：

```bash
cp sync.properties.example sync.local.properties
java -jar target/skill-downloader-1.0.0.jar --sync-list --config sync.local.properties
java -jar target/skill-downloader-1.0.0.jar --sync-once --config sync.local.properties
java -jar target/skill-downloader-1.0.0.jar --schedule --config sync.local.properties
```

三条 Java 命令按需要分别执行，不需要同时启动。修改 properties 后重启进程生效。

```properties
output.directory=sync-data
top=50
interval.minutes=360
item.delay.millis=1000
platforms=skills.sh,clawhub
skills.view=trending
skills.catalog=public
clawhub.sort=trending
```

| 字段 | 含义 |
| --- | --- |
| output.directory | 输出根目录；相对路径以进程 Working directory 为基准，不是配置文件所在目录 |
| top | 每个平台数量，1–50 |
| interval.minutes | 上一轮完成后的等待时间，1–525600 分钟；不是每天固定钟点的 cron |
| item.delay.millis | 每个下载处理完后的等待，0–60000 毫秒；默认串行 |
| platforms | `skills.sh,clawhub` 或任一平台；不可重复 |
| skills.view | `trending`、`hot`、`all-time`，默认 `trending` |
| skills.catalog | `public`（默认，公开页面，无需平台 Token）或 `api`（正式 API，需要凭证）；同时决定同步下载走快捷模式还是 API 模式 |
| clawhub.sort | `trending`、`downloads`、`stars`，默认 `trending` |

初次验证 ZIP 下载可设置 `top=1` 和 `platforms=clawhub`，避免直接下载 100 个。

## 4. 榜单协议和凭证

### skills.sh（不是 skill.sh）

#### 默认：公开页面模式，不需要 Token

```text
skills.catalog=public
trending -> GET https://skills.sh/trending
hot      -> GET https://skills.sh/hot
all-time -> GET https://skills.sh/
```

公开页面目前包含 Next.js 的 `self.__next_f.push` 数据块，程序把文本块按顺序拼接，解析榜单组件的 `initialSkills`，并核对 `view`。该数据包含页面上被来源分组折叠的条目，不是简单取 HTML 中前 50 个链接。按平台数据顺序保留前 50 项，校验 `source`、`skillId` 和重复条目；不执行网页 JavaScript，也不访问猜测的内部 API。

HTTP 仅新增允许 `skills.sh` 和 `www.skills.sh` 的三个榜单页面，支持域名跳转、不发送平台 Bearer Token，仍有 HTTPS、公私网地址检查、响应体大小上限和原有有限重试。自定义 `SKILLS_SH_API_BASE` 不会改变公开页面地址。

GitHub 来源使用现有快捷适配器定位单个技能后打包，不调用 skills.sh 详情 API。**非 GitHub 来源目前只列榜，不支持公开模式下载**，报告对应项为 `FAILED / SOURCE_UNAVAILABLE`，其他条目继续，不自动调用需要凭证的 API，也不从第 51 名补齐。公开榜单可成功列出 50 项，不等于 50 项都能成功下载。

这是一条页面解析兼容路径，**不是官方承诺稳定的免鉴权 JSON API**。结构缺失、候选不唯一或排序与请求不符时返回 `INVALID_RESPONSE`，而不是宣称成功或静默切榜。页面改版需要维护解析器；遇到访问拒绝不绕过访问控制。

#### 可选：正式 API 模式，需要 Token

显式配置 `skills.catalog=api` 才走下面的接口：

```text
GET https://skills.sh/api/v1/skills?view=trending&page=0&per_page=50
Authorization: Bearer <有效 OIDC Token>
```

使用 `data` 与 `pagination.hasMore`，页码从 0 开始，按响应顺序去重直到达到目标。`trending` 表示近期增长榜，`hot` 表示更短期的热度变化，`all-time` 表示累计榜。程序保留 `id/source/slug/sourceType` 生成技能详情链接；不把整个仓库当成单个技能。

通过 `SKILLS_SH_TOKEN_FILE` 指定由外部系统轮换的凭证文件（优先），或使用 `SKILLS_SH_TOKEN` 环境变量。已有受控 API 代理可使用 `SKILLS_SH_API_BASE` 配置；代理必须提供兼容协议，不要配置不可信主机。**程序不负责签发 OIDC Token，也不包含自动登录或 Nacos 客户端**。只有有效且拥有相应权限的凭证才可访问，不应把任意 GitHub Token 当成该凭证。

API 榜单模式配套使用 API 下载模式，支持 GitHub 和 well-known 来源。缺少或失效的凭证会使该平台失败，不阻断 ClawHub。同步任务以 `skills.catalog` 为准，不受网页/单项下载的 `SKILLS_SH_MODE` 设置影响；API 模式失败不会自动改用公开页面。

### ClawHub

```text
GET https://clawhub.ai/api/v1/skills?sort=trending&limit=50
```

使用 `items`，保留 `ownerHandle + slug` 防止同名技能混淆，并把 `latestVersion.version` 传给下载器固定版本。近期热门接口取一次窗口，不追踪 cursor；`downloads` 和 `stars` 模式使用 `nextCursor`。所有分页均有去重、重复游标检查和 20 页安全上限。

复用现有 ClawHub 适配器，优先处理平台提供的下载来源；并非假设每个技能都能找到 GitHub 仓库。公共榜单无需配置本项目的 skills.sh Token，但平台仍可能限流或拒绝访问。

两平台下载继续复用原 HTTP 限流重试策略，429/502/503/504 有限重试，并处理 `Retry-After`。批量 GitHub 来源建议配置 `GITHUB_TOKEN`，不保证无额度限制。凭证不要放进 properties 或提交到 Git。

接口依据（2026-10-28 核验）：

```text
https://skills.sh/docs/api
https://skills.sh/trending
https://skills.sh/hot
https://skills.sh/
https://github.com/openclaw/clawhub/blob/main/convex/httpApiV1/skillsV1.ts
```

## 5. 文件和报告

```text
sync-data/
  .sync.lock
  latest-run.json
  runs/<本轮时间-UUID>/
    report.json
    skills.sh-catalog.json
    clawhub-catalog.json
  artifacts/<平台>/<技能ID的SHA256>/
    <ZIP内容SHA256>.zip
    latest.json
  staging/
```

榜单文件只在该平台查询成功后生成。报告保存来源链接、名次、版本、实际数量、成功/失败状态和安全错误码。ZIP 路径相对输出根目录；可通过报告的 `file` 字段找到文件，而不必手工计算哈希目录名。

控制台每项日志包含技能 ID；失败同时输出错误码、异常类型与安全的具体原因，报告 `message` 同步保存。已识别的错误会显示解压超限、正文超时、ZIP 校验失败、目录匹配失败等；HTTP 错误显示状态码，嵌套异常最多展示 4 层。为避免 Token、带签名 URL 或远端响应泄露，不直接打印完整堆栈或任意异常原文；未分类错误保留异常类型并明确提示未分类。历史报告不会自动更新，修改后需重新启动任务生成新报告。

每项结果：`LISTED`（只列榜）、`DOWNLOADED`、`UNCHANGED`、`FAILED`。平台结果：`SUCCESS`、`INCOMPLETE`（不足目标）、`PARTIAL`（个别下载失败）、`FAILED`（榜单失败）。整轮所有平台成功才为 `SUCCESS`，否则 `PARTIAL`；执行中为 `RUNNING`，正常收到中断为 `INTERRUPTED`。

ZIP 下载后验证 SHA-256；同内容只存一份，变化后保留历史文件。已有文件损坏时重新保存。**这是落盘去重，不是免下载缓存：每轮仍下载文件再对比**。失败不更新该技能原有的 latest.json。榜单快照和报告长期保存，目前没有自动清理策略，请按磁盘容量自行配置保留策略。

报告每处理一项原子更新；输出目录文件锁防止同进程或不同进程重叠写入。异常退出、强制杀进程或磁盘错误可能留下 RUNNING 报告、临时文件；下次运行是新一轮，不是断点续传。确认没有运行中的任务后可清理遗留 staging 文件；锁文件本身存在不代表仍被占用，不要运行中删除它。

## 6. 对接已有定时平台

CLI 的 `--sync-once` 执行一次后退出：完整成功退出码 0，部分失败或数量不足退出码 2，参数/锁/文件系统等致命异常退出码 1。`--sync-list` 使用相同退出约定，但不下载。平台业务错误码和详情读 report.json，不要仅靠控制台文本。

外部 cron、XXL-JOB 或其他调度平台可调用一次性 CLI，也可在 Java 中调用：

```java
SyncConfig config = SyncConfig.load(Path.of("sync.local.properties"));
SkillSyncService service = new SkillSyncService(config, DownloadConfig.fromEnvironment());
SkillSyncService.RunResult result = service.runOnce(false);
```

调用方负责按 `result.status()` 判断成败、记录任务结果并处理异常。外部调度时不要另起 `--schedule`；同输出目录发生竞争时会快速失败，不会排队。内置调度启动立即执行，正常轮次或异常轮次结束后等待配置间隔，随后再试；不提供跨机器分布式锁、补跑或告警。若部署多个节点，应让调度平台保证单实例，文件锁不替代分布式调度。

## 9. 正式模式改为仅使用 skills.sh 文件快照

2026-10-29 调整：`skills.catalog=api`（同步）或 `SKILLS_SH_MODE=api`（单项/网页）下，GitHub 来源和域名来源统一使用详情 API 的 `files[].path`、`files[].contents` 在本地生成 ZIP，不再访问 GitHub API、codeload 或仓库下载地址。

```text
正式榜单 API → 正式详情 API → 校验所有文件 → 本地 ZIP
```

缺少文件、未知/二进制编码、非法路径、缺少根目录 SKILL.md 或超过既有 JSON/解压限制时明确失败；不静默回退、不跳过文件假装完整成功。当前支持平台返回的 UTF-8 文本文件快照，不保证平台快照包含仓库中的所有资源或与仓库最新提交一致。`hash` 是平台快照标识，ZIP SHA-256 由本地计算。

正式模式不接受 `--ref`、`--path`、`--skill`。公开榜单 `skills.catalog=public` 仍配套 GitHub 快捷下载；直接 GitHub 下载与 ClawHub 下载逻辑不变。此次调整不代表修复 GitHub 403，而是正式模式不再使用该下载链路。
